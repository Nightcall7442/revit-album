# Улучшение агента (накопление опыта)

Цель: ни одна ошибка не повторяется. Ошибка считается исправленной, только когда есть **тест, который падал до
исправления и проходит после**, и **урок** в `design-album/references/lessons.md` со стражем.

## Где лежит код
Плагин: `space-design-album/` → `skills/design-album/scripts/sdalbum/` (движок), `scripts/tests/` (тесты),
`references/lessons.md` (опыт), `examples/`, `cases/` (эталоны регрессии). Установленный плагин — только для
чтения: скопируй его в рабочую папку (`work/plugin/space-design-album`) и правь копию. Если в сессии есть скилл
`cowork-plugin` — используй его для правки и переупаковки установленного плагина.

## Процедура (строго по шагам)
1. **Зафиксировать симптом.** Лист, место, что не так, как должно быть (по `drawing-standards.md` / ГОСТ / замечанию).
2. **Воспроизвести.** Минимальные данные: мутация `examples/studio-minimal/project.json` (фикстура `make_project`)
   или конкретный лист эталона (`tests/test_sheets.py::_sheet`). Если ошибка в данных пользователя, а не в движке —
   это правило проверки данных (`sdalbum/validate.py`), а не правка отрисовки.
3. **Написать падающий тест** в подходящем файле `tests/test_*.py`: проверять смысл (позиция, значение, отсутствие
   пересечения), а не пиксели. Запустить — должен упасть по правильной причине.
4. **Исправить движок** минимально и в общем виде (не под один проект): правило размещения, проверка QA, правило
   данных. Новые коды проверок — уникальные, в кавычках в коде (их ищет test_lessons).
5. **Все тесты:** `cd scripts && python3 sda.py test` (включая медленную регрессию эталонов). Зелёное — обязательно.
   Если поменялось ожидаемое число листов/предупреждений эталона — обновить `expected.json` осознанно, с причиной.
6. **Урок:** добавить `## L-NNN` в `references/lessons.md` (симптом, причина, правило, `Страж:` код или тест).
7. **Эталон (если проект завершён):** `cases/<имя>/project.json` + `expected.json` (sheets, plan_scale,
   total_area, accepted_data_warnings, titles). Данные заказчика обезличить (meta), если он не разрешил иное.
8. **Версия:** увеличить `version` в `.claude-plugin/plugin.json` (исправление — патч, новая возможность — минор),
   дописать `CHANGELOG.md`.
9. **Упаковать:** `cd <корень плагина> && zip -r ../space-design-album-<версия>.plugin . -x "*/__pycache__/*" "*.pyc"
   "*/.pytest_cache/*"` и отправить файл пользователю (SendUserFile) с одной строкой, что изменилось.
   Пользователь устанавливает новую версию поверх старой.

## Чего не делать
- Не «исправлять» результат ручной правкой PDF/DXF или подгонкой координат только в одном проекте.
- Не ослаблять проверку, чтобы тест прошёл; не удалять уроки.
- Не выпускать версию с красными тестами.

## Постоянное развитие
- Каждое замечание заказчика по альбому → этот скилл (даже мелкое: одна строка урока + тест).
- Раз в несколько проектов: просмотреть предупреждения `LINE_THROUGH_TEXT` / `TEXT_AT_VP_EDGE` в qa.json эталонов
  и превратить повторяющиеся в правила размещения.
- Если пользователь хочет синхронизацию между компьютерами/сессиями — предложить завести GitHub-репозиторий плагина
  и коммитить каждую версию (`git tag v<версия>`).
