# Рабочий процесс: от исходников до сданного альбома

Все команды — из папки `scripts/` скилла: `python3 sda.py <команда>`. Рабочая папка проекта — новая папка в
рабочем каталоге сессии (`work/<объект>/`), исходники заказчика не изменяются.

## 0. Подготовка (1 раз за сессию)
`python3 sda.py doctor` — ставит ezdxf, shapely, pymupdf, matplotlib, pytest, mathutils и шрифт Inter.
`python3 sda.py test -m "not slow"` — быстрый прогон (секунды): движок исправен.

## 1. Одна команда
`python3 sda.py make <исходник|папка> work/<объект> [--revit --target-dir "C:\..."]` — основной путь. Внутри:
1. **Импорт** по типу: `.max` (import-max), `.dxf`/`.dwg` (import-dxf; DWG — через ODA/LibreDWG, иначе просим DXF),
   векторный `.pdf` (import-pdf: стены — тёмные заливки, масштаб — по размерным числам или `--scale`), фото/скан —
   статус `digitize` (оцифровка по `import-pdf-photo.md`). Тип проёма в разрыве стены — по нарисованному:
   рамы — окно, дуга — дверь, рамы + дуга в фасаде — балконная дверь, широкий внутренний разрыв — проём.
2. **fix** — безопасные исправления: шаг 5 мм, оси по центрам несущих стен и начало координат в 1/А, помещения по
   контуру стен (если названий нет), классы помещений по названиям, марки и типы проёмов, открывание дверей
   (входная наружу, санузлы наружу, комнаты внутрь; петли у угла, без удара в мебель), точки на стену, ГВС слева,
   проходные/перекрёстные, РВ в санузлах, буквы развёрток по часовой.
3. **propose** — только для ПУСТЫХ разделов, по нормам (`drawing-standards.md`, «Проектное предложение»): полы,
   потолки, отделка, сантехвыводы у приборов, светильники по освещённости, выключатели у входа со стороны ручки,
   розетки по СП 256 и мебели, кондиционер, щит, группы. Всё помечено `proposed` и попадает в вопросы заказчику.
4. **validate** → **build** (PDF, DXF, PNG) → **QA** листов → (`--revit`) пакет Revit → `report.md` / `report.json`.

Рабочая копия — `work/<объект>/project.json` с журналом (`history`, `undo`, `diff`); исходник не меняется.
Повторный `make` с тем же исходником сохраняет правки рабочей копии; изменился исходник — копия обновляется
(прежняя остаётся в журнале).

## 2. Что спросить у заказчика (если не сказано и не видно в исходнике)
Высота до плиты и чистовой потолок; назначение помещений, если их нет на чертеже; что сохраняется (стены, двери);
пожелания по составу листов; реквизиты студии. Не спрашивать то, что можно измерить в исходниках, и то, что
`propose` закрывает нормой, — это идёт в отчёт как предложение.

## 3. Ручная доработка project.json (когда автоматики мало)
Мебель из 3D-сцены, развёртки санузлов и кухни, потолочные зоны и узлы, особые решения дизайнера — по
`project-schema.md` (примеры: `../examples/*`). Правки — через `sda.py edit` (журнал и проверка после каждой).
**Нормализация данных модели** (урок L-011): координаты и размеры — кратно 5 мм, модули выровнены, зазоры < 15 мм
либо убраны, либо объяснены (планка, шов). Не переносить шум 3D-модели в чертежи.

## 4. Проверка данных
`sda.py validate work/project.json` — **0 ошибок**. Каждое предупреждение — либо исправить, либо осознанно принять и
сообщить заказчику (конфликт двери с мебелью — это вопрос дизайна, а не чертежа).

## 5. Сборка альбома
`sda.py build work/project.json work/out --png` → `album.pdf`, `album.dxf`, `png/sNN.png`, `qa.json`.
Итог в конце вывода: `ИТОГ: ошибок 0, …`. Ошибки QA листа / данных / сборки (CONTENT_CLIPPED, COLUMN_OVERFLOW) —
блокируют выдачу.

## 6. Визуальная приёмка (обязательно, автоматика не видит смысл)
Открыть КАЖДЫЙ `png/sNN.png` и пройти `qa-checklist.md`. Типичные находки: подпись далеко от объекта, странная
привязка, пустой лист, лишняя цепочка, не тот масштаб, неверная ссылка. Нашли — исправить данные или движок
(движок — через improve-agent: тест → правка → все тесты) и пересобрать.
Для крупных проектов — независимая проверка отдельным агентом, который не видел процесс: дать ему PDF, project.json
и чек-лист, попросить список замечаний с номерами листов.

## 7. Выдача
- PDF альбома (+ DXF для доработки в AutoCAD), отчёт (`report.md`): состав листов, что принято как проектное
  предложение, вопросы к заказчику. Для повторной выдачи — `sda.py diff project.json --since N`: список изменений
  словами и затронутые листы.
- Revit (по запросу): `sda.py revit work/project.json work/revit` → `.dyn` для Dynamo / `.py` для pyRevit; инструкция
  — `revit.md`. Действия на ПК пользователя — только с его разрешения.

## 8. Опыт
После выдачи: всё, что пришлось исправлять вручную, и все замечания заказчика → `improve-agent` (урок, тест, правило).
Завершённый проект можно добавить эталоном в `cases/<имя>/` (project.json + expected.json) — он войдёт в регрессию.
